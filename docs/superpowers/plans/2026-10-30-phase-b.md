# Phase B: a customer's full runtime (S4.5 B, with S4.6 A and S4.7 A1)

Status, 30 Oct: Phase A is on `feat/saas-s1` (08cd130). The Supervisor runs with `PLATFORM_ENABLED`, the founder is
adopted, and every customer has a setup shell. `scope(tenantId)` answers every customer 503. Already done:
- S4.1 (data keys) and S4.2 (AiKeys);
- S4.6 B (the gateway guarded);
- S4.7's lane B helpers (`oauthState.ts`, `transcriberChoice`);
- S4.7 A2 (`sttEnvFor` in S4.4).

This file says who changes what so that a customer's runtime does real work with only its own key, files, Db and data
key. Nothing here changes the founder's runtime: the founder's profile is today's env and the master key.

## The idea: a customer profile, not new parameters everywhere

Most modules already take their folder and key from the runtime:
- `createApp({ dataDir })` hands it to the media processor, the uploader, the meetings and health;
- `MediaRefSealer(key)`, `TokenStore(db, key)`, `useEncryptedAuthState(db, key)` and the group-key subkey take the key
  they are given.

So the customer runtime gets a **profile**: its own copy of the env, its own data key and its own Db. Each module
then reaches the right customer without changing.

| The runtime gets | Founder (unchanged) | Customer (Phase B) |
|---|---|---|
| `env.DATA_DIR` | `DATA_DIR` | `DATA_DIR/tenants/<id>` (made at start, 0700) |
| `key` (sealing, sessions, tokens, group keys) | the master key | `TenantKeys.dataKey(id)` |
| `db` | tracker.db / founder's `PgTenantDb` | `customerDbsOf(db)(id)` (Postgres only) |
| Claude key | `ANTHROPIC_API_KEY` | `AiKeys.load()`; none means setup-only (Phase A's shell) |
| groups | `config/allowed-groups.json` + watcher | the customer's own `clients` rows (no file, no watcher) |
| speech | as set | `sttEnvFor` (D2): local or none, no `STT_API_KEY` |
| spend | `DAILY_SPEND_CAP_USD` + `GlobalSpend` | its `dailySpendCapUsd`, no `platform` (D3) |
| report, heartbeat, UptimeRobot | as set | off: `REPORT_*`, `HEARTBEAT_URL` and `UPTIMEROBOT_READ_KEY` removed from its env |
| meetings settings | `TEAM_EMAIL_DOMAINS`, `MEETINGS_*` | off in Phase B (needs the customer's own settings: a later task) |

## Lane A (wa-agent-15)

1. **`src/runtime/customerProfile.ts` (new): `customerProfile(env, { tenantId, dataKey, aiKey })`.** Returns the
   customer's env copy, built from an allow-list of keys, not a deny-list. Only keys a customer runtime may read are
   copied; everything else is absent. The allow-list:
   - the engine and dashboard plumbing (`DB_ENGINE`, `DASHBOARD_*` without `DASHBOARD_OWNER_EMAILS`, `PLATFORM_*`, `AI_MODEL`, `AI_EFFORT`, prices);
   - the batching settings (`QUIET_MINUTES`, `MAX_WAIT_MINUTES`, `MAX_PARALLEL_CLIENTS`);
   - `DATA_DIR` replaced, and `ANTHROPIC_API_KEY` replaced by the customer's key;
   - `sttEnvFor`'s speech settings;
   - `MEETINGS_ENABLED=false` and `REPORT_ENABLED=false`.
   Test: an env Proxy shows the customer runtime never reads `GROUPS_FILE`, `STT_API_KEY`, `HEARTBEAT_URL`,
   `UPTIMEROBOT_READ_KEY`, `DASHBOARD_OWNER_EMAILS` or the founder's `ANTHROPIC_API_KEY`.
2. **`src/runtime/customerRuntime.ts`:**
   - `buildCustomerRuntime(t, deps)` takes the profile for a customer;
   - groups come from `listClients(db)` instead of a file;
   - `watchGroupsFile` is the founder's only;
   - the GroupDirectory and Open chat reach the customer's own gateway;
   - `requireKey(env, 'ANTHROPIC_API_KEY')` reads the profile's key.
3. **`src/runtime/platformSupervisor.ts`:** the factory starts a full runtime for an `active` customer with a key, and
   the setup shell otherwise (onboarding, or no key).
4. **`src/web/mountRoutes.ts` (scope):** `inScope(s)` becomes `scope(s.tenantId)`. It returns the running full
   runtime's route deps, or 503 while there is none. The routes then use the scope's deps, not the founder's fixed ones.
   This is the only place a customer starts reaching data, so it carries its own route-sweep variant (below).
5. **S4.6 A, `src/wa/authState.ts`, `src/wa/linkSession.ts` and `src/wa/senderGateway.ts`:**
   - a customer's session is its own `wa_auth` rows through its `PgTenantDb` (already true after S2.6c2: `sessionHomeOf` with the customer's Db);
   - the key passed is its data key, the same derivation as today with the master key swapped;
   - `readFounderNumber` and `FounderNumberWatch` stay founder-only; a customer's spare phone is a later task.
   Test: two customers link (fake sockets), and each one's `creds` opens only with its own data key.
6. **S4.7 A1, `src/web/routes/google.ts`:**
   - the connect start signs `state` with `signOAuthState(oauthStateKey, { tenantId: session.tenantId, account, at })`, where `oauthStateKey = deriveSubkey(master, 'wa-agent oauth state v1')` is made once in main.ts;
   - the callback verifies it first: a bad or expired state gets 400, another customer's 403, and nothing is stored;
   - the token goes to that customer's `TokenStore(tenantDb, dataKey)`.

## Lane B (a0): only where a runtime-supplied value cannot reach today

1. **`src/stt/local.ts`: one engine for the process, folders per customer.**
   - Problem: `sharedLocalEngine(env)` makes one engine per runtime, so N customers can run N models at once. Its work folders must also sit inside one `tmpDir`.
   - Wanted: `processLocalEngine(env)`, made once in main.ts, with the runs queued one at a time as today. Its `transcribe(..., { tmpDir })` takes the caller's folder, which must be inside one of the engine's allowed roots (`DATA_DIR/tmp` and `DATA_DIR/tenants/*/tmp`), checked the way `inside` is checked today.
   - Callers in lane A pass the runtime's folder.
   - Test: two runtimes' runs queue one at a time; a folder outside the roots is refused.
2. **`src/meetings/localTranscriber.ts` and `src/meetings/audio.ts`:**
   - they already take `tmpDir` and `dataDir` from deps, so no change, unless (1) changes the engine interface, in which case follow it;
   - `cleanupTemp(db, dataDir, log)` is per runtime already.
3. **`src/voiceDeps.ts` (whose? lane A if no one claims it):** `buildVoiceDeps(env, ...)` reads `env.DATA_DIR`, which
   the profile handles, so no change.
4. **`src/output/googleAuthHub.ts`, `src/output/googleAuth.ts` and `src/meetings/multiAccount.ts`:**
   - `GoogleAuthHub.open({ db, key })` and `TokenStore(db, key)` already take both, so no change for Drive;
   - the meetings accounts are off for customers in Phase B;
   - Wanted from B, only if B sees one: any module-level cache keyed by account label alone (not by db). Two customers' "main" accounts must never share a cached client. Test: two hubs with different db and key never share a client.
5. **`src/output/drive.ts` and `src/output/folders.ts`:** the tracker folder is found or made in the account that
   `drive` is built from, which is already per customer. Wanted from B: confirm that no folder id is cached across hubs;
   otherwise no change.
6. **`src/media/ref.ts` (`MediaRefSealer`):** takes the key, so no change. Confirmation test (B): a reference sealed
   with customer A's key does not open with B's.

## Lane C (c7)

- `views/onboarding.js`: the WhatsApp and spare panels show the customer's own link QR (S4.6 C).
- Phase A's `probes` already read the setup facts. With a full runtime, its `facts()` (whatsappLinked, driveConnected)
  come from the runtime's gateway and hub. That is lane A's change in `buildCustomerRuntime`, so nothing for C.

## Tests that gate Phase B (lane A)

- **Customer route sweep, data variant.** Two customers, A and B, each with one client, a task and a message. With A's
  session, every read route answers only A's rows. B's client code in the path gives 404, and the founder's gives 404.
  No response body contains B's or the founder's names, codes or group ids. Mutation check: point `scope` at the
  founder's deps, and the test must fail.
- **No founder material in a customer runtime.**
  - an env Proxy (above);
  - `ANTHROPIC_API_KEY` never read;
  - the customer's `DATA_DIR` is `tenants/<id>` and every file it writes is under it (a check of the folder after a batch with a media file);
  - its data key, not the master key, opens its sealed values.
- **Spend.** A customer's Claude calls never move `GlobalSpend`, and its `dailySpendCapUsd` stops it.
- **On SQLite nothing changes.** Customers are refused, as today.
