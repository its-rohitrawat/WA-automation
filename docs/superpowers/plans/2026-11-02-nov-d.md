## 3. Settings: remove the ban-risk note

- `views/settings.js`: drop the warning note from `sendingCard`. The switch, its one-line explanation, the limits
  sentence (moved into the switch's small text) and the audit sentence stay. The confirm dialog on switching on stays.
- Test: a new `tests/web/settingsView.test.ts` draws the card (export `sendingCard`) and checks there is no "Ban risk"
  note and that the switch, the limits and the audit words are there.

## 6. Keywords: add one at a time

- One shared helper in `views/priorityPanel.js`: `splitKeywords(text)` (split at commas, trim, single spaces) and
  `addKeywords(list, text, limits)` (duplicates in any case ignored; returns what was added and any problem).
- Priority keywords (Settings): each level has an input, an **Add** button (Enter adds too, a comma no longer adds on
  its own: pasting "a, b" adds both), and the chips below it, each with a remove button.
- Meeting keywords (Groups drawer): the same input + Add + chips, kept in the drawer's own list until "Add client" /
  "Keep changes". Client email domains stay a comma field.
- Tests: `tests/web/priorityPanel.test.ts` gets the new helpers and the new markup (Add button, chips below, esc()).

## 9. Groups select all

- `views/groups.js`: the Select all control becomes a real tri-state checkbox with its count ("Select all 12",

  for some; Select all with some ticked ticks the rest. Keep `#g-all` (the smoke script uses it).
- CSS in `styles.css`.

- Chart: one y axis with 3 to 4 round ticks in US$, a recessive grid, the cap as a dashed line with its label inside

## 5. The morning message editor

- `src/report/morningReport.ts`: `MESSAGE_PLACEHOLDERS` (what the report code really has: `{greeting}`, `{date}`,
  `{summary}`, `{open}`, `{overdue}`, `{critical}`, `{due_today}`, `{clients}`, `{tracker_link}`), `messageValues(view,
  today, link)`, `fillMessage(template, values)` (one pass; an unknown placeholder stays as written; never throws),
  `DEFAULT_MESSAGE = "{greeting}. {summary}. Today's tracker: {tracker_link}"`, so the default text is the same as today's
  `buildShortMorningText`, which becomes the default template filled in.
- `src/config/settingsStore.ts`: a new key `reportMessage` (a string, up to 1000 characters, not blank; the default text
  or `null` resets it to the default). No schema change (the settings table already holds any key). Audited.
- `src/report/scheduler.ts`: an optional `message` getter; the build uses the saved text, and falls back to the default
  text if anything about it fails, so the 08:00 send never fails on it. `liveReport.ts` and `dashboardReport.ts` pass it.
- Route (borrowed, asked): `GET /dashboard/api/settings/report-message` gives the text, the default, the limit and the
  placeholders with today's real values.
- `views/automations.js`: the editor (textarea, placeholders listed beside it, click to insert), a live preview with
  today's numbers, a character count, **Reset to default**, Save. Unknown placeholders are named under the preview.
- Tests: morningReport (fill, values, default equals old text), settingsStore (key checks, reset, audit), scheduler
  (custom text sent; a broken template falls back), route.
