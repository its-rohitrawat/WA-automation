**Goal:** the public site at `waagent.agentsolutionbowl.si/`, rebuilt properly from the approved mockups as a static export. **Architecture:**
- Next.js (App Router) with `output: 'export'` and TypeScript. Each homepage section is its own component.
- GSAP ScrollTrigger runs the scroll scenes, in client components with cleanup on unmount (`gsap.context`).
- Three.js runs the hero core and the ending planet, in isolated client components that pause when off screen.
- No Framer Motion: don't mix it with GSAP.
- No data from the agent; all demo data is labelled.

**Tech stack** (pin exact versions, at least two weeks old, in `package.json`): `next`, `react`, `react-dom`, `typescript`, `gsap`, `three`, `@hugeicons/react`, `@hugeicons/core-free-icons`, `geist`, `eslint`, `@playwright/test` (dev), `vitest` (dev, for the export check). No `wrangler` and no hosting tools.

**Spec:** sections 3, 7, 8, 9.

**Ground rules:**
- No secrets in the site. The demo form uses a form service's public form id from `src/config/site.ts`.
- No client data, no agent API calls.
- Tests and checks before each commit:
  - `npm run lint`, `npm run typecheck` and `npm run build`;
  - the Playwright crawl (task 9).
- Accessibility: semantic HTML, focus states, keyboard access for the menu, accordion and wheel, alt text, and reduced motion (no pins and no WebGL motion; static layouts instead).
- Respect the design tokens from the mockup exactly (WhatsApp palette, Geist, the validated status colours).

## Task 8: Export for the agent (no Worker, no deploy)

- The WA Agent serves the site itself on the Mac, at `/`, beside `/dashboard`. Nothing is deployed from here: the owner merges, and the Mac updates itself. This replaces the Cloudflare Pages and Worker routing in spec section 9 (owner decision, 27 Oct; see the spec's amendment).
- `npm run build` writes the static export to `out/`, and it works from a plain static server at the site root. Every page and asset uses root-relative paths. No `basePath` and no server features: no API routes, no middleware, no `next/headers`, no runtime image optimisation.
- The site links only to `/dashboard` itself (the sign-in entry). Nothing in `out/` lives under a `dashboard` path.
- Add `scripts/export-check.mjs` (`npm run export:check`). After a build it walks `out/` and fails on: a `<script>` or stylesheet loaded from another origin (fonts and scripts must be self-hosted), a file over 2 MB, a path starting with `dashboard`, a `.map` file, or a string that looks like a secret (`sk-`, `AKIA`, `-----BEGIN`).
- `EXPORT.md` lists what the agent must serve: the folder, the content types (from the file extensions in `out/`), the HTML files with inline `<script>` tags (the agent's site CSP must allow them by hash), and the 404 page (`out/404.html`).
- Don't create any Cloudflare, Pages, Worker, `wrangler` or hosting config. Don't add a git remote or push.
- **Tests** (vitest, `tests/export-check.test.ts`) run the checker on a small fake `out/` folder:
  - a clean folder passes;
  - a script from another origin fails;
  - a `.map` file fails;
  - a secret-looking string fails.
