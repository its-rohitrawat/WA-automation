# SaaS S1 and S2 Implementation Plan: async store layer, then Postgres with RLS

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every database call behind one async interface while still on SQLite (S1, no visible change), then add Postgres 17 with forced row level security behind `DB_ENGINE=sqlite|postgres` (S2), with the whole test suite green on both engines.

**Architecture:** One `Db` interface (`get`/`all`/`run`/`exec`/`tx`) replaces direct better-sqlite3 use. On SQLite it is a single connection behind an explicit FIFO queue, with async transactions as `BEGIN IMMEDIATE … COMMIT` held by the queue. On Postgres it is a tenant-bound handle: every statement and transaction runs inside `withTenant(tenantId, …)`, which opens a transaction, sets `app.tenant_id` with `set_config(…, true)`, and takes a per-tenant advisory lock for writes. The tables carry `tenant_id` with RLS `ENABLE` + `FORCE`, and the agent connects as `wa_app` (`NOBYPASSRLS`, not the owner).

**Tech Stack:** Node 24 (TypeScript run directly), better-sqlite3 (today), `pg` 8.23.x (node-postgres), Postgres 17, vitest, Docker `postgres:17-alpine` (Windows tests) or Homebrew `postgresql@17` (Mac tests).

**Design:** [docs/superpowers/specs/2026-10-29-saas-multi-tenant-design.md](../specs/2026-10-29-saas-multi-tenant-design.md), sections 4.1, 4.2, 8 and 10. Owner decisions (29 Oct): Postgres with real RLS; each customer brings their own Anthropic key (S4, not here).

**Out of scope here:** the copy tool (S3), the Supervisor and per-customer runtimes, keys and caps (S4), invites, sign-up and the Customers screen (S5), the cutover (S6).

## 2. S1 design decisions

### 2.1 One interface for both engines

`src/store/engine/types.ts` holds the only database API the rest of the code uses after S1:

```ts
/** Positional values (`?`) or named values (`@name`). Booleans are never passed: flags are 0 and 1. */
export type Params = readonly unknown[] | Readonly<Record<string, unknown>>;

export interface RunResult {
  /** Rows written by the statement. */
  changes: number;
}

/** A connection, or a transaction on one. */
export interface Sql {
  get<T>(sql: string, params?: Params): Promise<T | undefined>;
  all<T>(sql: string, params?: Params): Promise<T[]>;
  run(sql: string, params?: Params): Promise<RunResult>;
  /** Several statements and no values: migrations and PRAGMAs only. */
  exec(sql: string): Promise<void>;
  /** A transaction; inside one, a savepoint. fn must use the handle it is given, and must not wait on the network. */
  tx<T>(fn: (q: Sql) => Promise<T>): Promise<T>;
}

export interface Db extends Sql {
  readonly engine: 'sqlite' | 'postgres';
  close(): Promise<void>;
}
```

- `Db` keeps today's type name, so every `db: Db` parameter in the code stays as it is. Only the calls change: `db.prepare(S).get(a, b)` becomes `await db.get(S, [a, b])`.
- `lastInsertRowid` is not part of the interface. The 4 sites that need a new id use `INSERT … RETURNING id` through `get()`. SQLite has supported RETURNING since 3.35, and better-sqlite3 12 bundles 3.49. These four are converted in S1, so S2 has nothing left to change there.

### 2.2 Transactions, which better-sqlite3 runs synchronously

`db.transaction(fn)` in better-sqlite3 commits when `fn` returns. With an `async` function, that is at its first `await`, so the rest would run outside the transaction. It can't take async work. The replacement is `db.tx(async (q) => …)`:

- **On SQLite:**
  - it waits its turn in the queue (2.3);
  - then it runs `BEGIN IMMEDIATE`, as today's `tx()` does with `.immediate()`;
  - then it awaits `fn(handle)`, then `COMMIT`, or `ROLLBACK` on any throw;
  - the queue is held for the whole transaction, so nothing else on the connection runs in between.
- **Nested `q.tx(…)`** becomes `SAVEPOINT sp<n>` / `RELEASE` / `ROLLBACK TO`. Nesting happens today: `runProposal` wraps `runTaskAction`, and the corrections call `tx` inside `tx`.
- **A deadlock guard:**
  - Inside a transaction, a call on the outer `db` would wait for the queue its own transaction holds.
  - `AsyncLocalStorage` marks the transaction's async context, and the outer `db` throws `TxMisuseError('inside db.tx, use the transaction handle')` in that context.
  - The same rule is what keeps RLS correct in S2, where the outer handle is another connection.
- **A long transaction is a bug.** `tx` measures its own time and logs a warning above 2 s. Under `NODE_ENV=test` it throws instead (`TX_MAX_MS`), so a transaction that waits on the network fails a test rather than holding the database.

### 2.3 Keeping the single writer

**Today:** the single writer is not an object in the code. It holds because better-sqlite3 is synchronous: a transaction runs from start to end in one JavaScript turn, and nothing else can run between a check and its write.

**After S1:**
- **SQLite:** `SqliteDb` makes the single writer explicit with a FIFO `SerialQueue`. Every operation goes through it, reads included, so a read never sees a half-done transaction. Throughput is unchanged, because each statement still takes microseconds.
- **Another process** (the CLI while the service runs) is unchanged: the SQLite file lock, `busy_timeout = 5000` and `BEGIN IMMEDIATE`.
- **Postgres (S2):**
  - a write transaction takes `pg_advisory_xact_lock(hashtextextended('wa:' || tenant_id, 0))` first. That is a single writer **per customer**, which keeps every check-then-write pattern in the code correct, while different customers run in parallel;
  - plain reads take no lock;
  - single-statement claims (`claimReport`, the media claims) stay atomic by themselves;
  - a single statement through `db.get`/`db.run`, including `INSERT … RETURNING id`, takes no lock either, because one statement is atomic on its own. The lock protects the multi-statement transactions (`db.tx`), which are the check-then-write patterns.

### 2.4 The synchronous readers

Each one keeps a synchronous getter over state held in memory. The state is loaded with `await` at start and kept current by the writer:

- **`SpendGuard`:**
  - `await guard.load()` reads today's totals by kind;
  - `record()` and `settle()` update the in-memory totals synchronously, then write the row through the queue;
  - `isPaused()`, `spentToday()`, `fits()` and `reserve()` stay synchronous, so the reservation logic doesn't change;
  - the app tick runs `await guard.refresh()` (at most every 30 s) to pick up spend another process booked (the CLI), and a day change resets the totals;
  - if a write fails, the error is logged and the in-memory total stays. That over-counts, which is safe under a cap.
- **`SettingsStore`:** it keeps the rows in a `Map`, loaded by `await store.load()`, and updates the map after each saved `set()`. The CLI changes no settings.
- **`HistoryBackfill.held()`:** it reads `#active` (memory) plus a cached `fetchingSince`, written by `#stepOnce` and `#finish`.
- **`Health`:** `snapshot()` stays synchronous. The kv read it does becomes a value refreshed by the 30 s health tick, and the `setKv` write becomes `await`.
- **The Baileys handlers:** each gateway gets an `#inbound = Promise.resolve()` chain, and every event becomes `this.#inbound = this.#inbound.then(() => handle(e)).catch(log)`. Events are then ingested one after another, in the order they came, as today.

### 2.5 The order that keeps the tests green

Making a function `async` forces each caller to `await` it, and so upward. S1 converts **from the top down**, starting where the callers are already async: the route handlers, the ticks and the CLI command bodies. A converted function may go on calling unconverted ones, through `db.raw` (2.6). The most-imported store modules (`kv`, `clients`, `tasks`, `messages`) go last, when most of their callers are already async, so their ripple is small.

### 2.6 The temporary `raw` handle, removed at the end of S1

`SqliteDb.raw` is the better-sqlite3 handle. Task S1.2 rewrites every `db.prepare(` to `db.raw.prepare(` and every `tx(db, fn)` to `txSync(db, fn)` mechanically, so everything works on the new type from the first commit. Each later task removes its own files' `raw` use.

**The guard:** while an async transaction holds the connection, `raw` throws `TxMisuseError`, unless the caller is inside that same transaction's async context. That way an unconverted synchronous write can never slip into another flow's open transaction.

A ratchet test (S1.0) lists the files still allowed to use `raw` or `txSync`. Each task deletes its lines from the list, and S1.15 deletes `raw`, `txSync` and the list. **S1 is never released before S1.15**: the intermediate commits only need to be green.

### 2.7 Tests

- `tests/helpers/db.ts` becomes async: `await seededDb()`, `await openTestDb()`.
- Every test that calls a converted function adds `await`.
- vitest runs async tests natively.
- A converted test that forgets `await` fails on the typecheck: `expect(promise).toEqual(row)` compares a Promise with a row, and `tsc --noEmit` with `@typescript-eslint/no-floating-promises` is not set up here. So every task runs `npm run typecheck` **and** its tests.

```ts
import { readdirSync, readFileSync } from 'node:fs';
import { join } from 'node:path';

const SRC = 'src';
const rows: { file: string; prepare: number; tx: number; raw: number }[] = [];
for (const f of readdirSync(SRC, { recursive: true, encoding: 'utf8' })) {
  if (!f.endsWith('.ts')) continue;
```

```ts
/** First in, first out: each job starts when the previous one has settled, whatever its outcome. */
export class SerialQueue {
  #tail: Promise<unknown> = Promise.resolve();

  run<T>(job: () => Promise<T>): Promise<T> {
    const next = this.#tail.then(job, job);
    this.#tail = next.then(() => undefined, () => undefined);
    return next;
  }
```

- [ ] **Step 4: Write the engine**

```ts
// src/store/engine/sqlite.ts
import { AsyncLocalStorage } from 'node:async_hooks';
import { mkdirSync } from 'node:fs';
import { dirname } from 'node:path';
import Database from 'better-sqlite3';
import { SerialQueue } from './queue.ts';
import type { Db, Params, RunResult, Sql } from './types.ts';

/** Using the outer handle inside a transaction, or raw while another flow holds one. */
export class TxMisuseError extends Error {
  constructor(message: string) {
    super(message);
    this.name = 'TxMisuseError';
  }
}

const inTx = new AsyncLocalStorage<SqliteDb>();
const STATEMENTS_MAX = 500;

function bind(params?: Params): unknown[] {
  if (params === undefined) return [];
  return Array.isArray(params) ? [...params] : [params];
}

/** better-sqlite3 behind the async interface: one connection, every call in one FIFO queue (the single writer). */
export class SqliteDb implements Db {
  readonly engine = 'sqlite' as const;
  readonly #raw: Database.Database;
  readonly #queue = new SerialQueue();
  readonly #statements = new Map<string, Database.Statement>();
  readonly #txMaxMs: number;
  #held = false;
  #savepoints = 0;

  private constructor(raw: Database.Database, o: { txMaxMs?: number }) {
    this.#raw = raw;
    this.#txMaxMs = o.txMaxMs ?? (process.env.NODE_ENV === 'test' || process.env.VITEST ? 1_000 : 0);
  }

  /** Opens the file with today's pragmas. The caller migrates (store/db.ts). */
  static open(file: string, o: { txMaxMs?: number } = {}): SqliteDb {
    if (file !== ':memory:') mkdirSync(dirname(file), { recursive: true });
    const raw = new Database(file);
    raw.pragma('journal_mode = WAL');
    raw.pragma('foreign_keys = ON');
    raw.pragma('busy_timeout = 5000');
    raw.pragma('secure_delete = ON');
    return new SqliteDb(raw, o);
  }

  /** S1 only (removed in S1.15): the better-sqlite3 handle, for code not converted yet. */
  get raw(): Database.Database {
    if (this.#held && inTx.getStore() !== this) throw new TxMisuseError('a synchronous statement ran while another flow holds a transaction');
    return this.#raw;
  }

  #stmt(sql: string): Database.Statement {
    let s = this.#statements.get(sql);
    if (!s) {
      if (this.#statements.size >= STATEMENTS_MAX) this.#statements.clear();
      s = this.#raw.prepare(sql);
      this.#statements.set(sql, s);
    }
    return s;
  }

  #outside(): void {
    if (inTx.getStore() === this) throw new TxMisuseError('inside db.tx, use the transaction handle');
  }

  /** The handle a transaction's fn gets: the same connection, no queue (the transaction holds it). */
  #handle(): Sql {
    const now = <T>(fn: () => T) => Promise.resolve().then(fn);
    return {
      get: (sql, p) => now(() => this.#stmt(sql).get(...bind(p)) as never),
      all: (sql, p) => now(() => this.#stmt(sql).all(...bind(p)) as never),
      run: (sql, p) => now(() => ({ changes: this.#stmt(sql).run(...bind(p)).changes })),
      exec: (sql) => now(() => void this.#raw.exec(sql)),
      tx: (fn) => this.#savepoint(fn),
    };
  }

  async #savepoint<T>(fn: (q: Sql) => Promise<T>): Promise<T> {
    const name = `sp${++this.#savepoints}`;
    this.#raw.exec(`SAVEPOINT ${name}`);
    try {
      const r = await fn(this.#handle());
      this.#raw.exec(`RELEASE ${name}`);
      return r;
    } catch (e) {
      this.#raw.exec(`ROLLBACK TO ${name}`);
      this.#raw.exec(`RELEASE ${name}`);
      throw e;
    }
  }

  get<T>(sql: string, p?: Params): Promise<T | undefined> {
    this.#outside();
    return this.#queue.run(async () => this.#stmt(sql).get(...bind(p)) as T | undefined);
  }

  all<T>(sql: string, p?: Params): Promise<T[]> {
    this.#outside();
    return this.#queue.run(async () => this.#stmt(sql).all(...bind(p)) as T[]);
  }

  run(sql: string, p?: Params): Promise<RunResult> {
    this.#outside();
    return this.#queue.run(async () => ({ changes: this.#stmt(sql).run(...bind(p)).changes }));
  }

  exec(sql: string): Promise<void> {
    this.#outside();
    return this.#queue.run(async () => void this.#raw.exec(sql));
  }

  tx<T>(fn: (q: Sql) => Promise<T>): Promise<T> {
    this.#outside();
    return this.#queue.run(async () => {
      const started = performance.now();
      this.#raw.exec('BEGIN IMMEDIATE');
      this.#held = true;
      try {
        const r = await inTx.run(this, () => fn(this.#handle()));
        const ms = performance.now() - started;
        if (this.#txMaxMs > 0 && ms > this.#txMaxMs) throw new Error(`a transaction held the database for ${Math.round(ms)} ms`);
        this.#raw.exec('COMMIT');
        return r;
      } catch (e) {
        if (this.#raw.inTransaction) this.#raw.exec('ROLLBACK');
        throw e;
      } finally {
        this.#held = false;
      }
    });
  }

  async close(): Promise<void> {
    await this.#queue.run(async () => this.#raw.close());
  }
}
```

### The conversion patterns, used by tasks S1.3 to S1.14

Every conversion task applies these patterns to its files. Then it adds `await` up to the first caller that is already async, removes its files from the allowlist, and runs the checks.

| Before | After |
|---|---|
| `db.raw.prepare(S).get(a, b) as R \| undefined` | `await db.get<R>(S, [a, b])` |
| `db.raw.prepare(S).get({ x }) as R` | `(await db.get<R>(S, { x }))!` when the row always exists, else keep `\| undefined` |
| `db.raw.prepare(S).all(a) as R[]` | `await db.all<R>(S, [a])` |
| `db.raw.prepare(S).run(a).changes` | `(await db.run(S, [a])).changes` |
| `Number(db.raw.prepare(INSERT).run(v).lastInsertRowid)` | `(await db.get<{ id: number }>(INSERT + ' RETURNING id', v))!.id` |
| `txSync(db, () => { … })` | `await db.tx(async (q) => { … })`, with every call inside on `q`, never `db` |
| `export function f(db: Db, …): T` | `export async function f(db: Sql, …): Promise<T>` (`Sql` accepts both a `Db` and a transaction handle) |
| A function inside `txSync` calling store functions | those store functions take `q: Sql`, and the caller passes `q` |
| A test: `expect(f(db)).toEqual(x)` | `expect(await f(db)).toEqual(x)` |
| A test: `expect(() => f(db)).toThrow(E)` | `await expect(f(db)).rejects.toThrow(E)` |

Worked example, `store/kv.ts`, the whole file after its conversion in S1.12:

```ts

export async function deleteKv(db: Sql, k: string): Promise<void> {

```

```ts
export async function migrate(db: Db, migrations: readonly Migration[] = MIGRATIONS): Promise<void> {
  await db.exec('CREATE TABLE IF NOT EXISTS schema_version (version INTEGER NOT NULL)');
  let current = (await db.get<{ v: number | null }>('SELECT MAX(version) AS v FROM schema_version'))?.v ?? 0;
  const recorded = new Set((await db.all<{ version: number }>('SELECT version FROM schema_version')).map((r) => r.version));
  const skipped = migrations.filter((m) => m.version < current && !recorded.has(m.version)).map((m) => `v${m.version}`);
  if (skipped.length > 0) {
    const verb = skipped.length === 1 ? 'was' : 'were';
    throw new Error(`database is at v${current} but ${skipped.join(', ')} ${verb} never applied; restore a backup or contact the developer`);
  }
  for (const m of migrations) {
    if (m.version <= current) continue;
    await db.tx(async (q) => {
      await q.exec(m.sql);
      await q.run('INSERT INTO schema_version (version) VALUES (?)', [m.version]);
    });
    current = m.version;
  }
}
```

## 4. S2 design decisions

### 4.1 The library: `pg` (node-postgres) 8.23.x

Checked on 29 Oct 2026 with `npm view`:
- `pg` is at 8.23.1, published 30 Sep 2026. It is actively maintained (brianc/node-postgres) and the most used Postgres driver for Node.
- **No install scripts:** `pg` declares only a `test` script.
- Its dependencies `pg-pool` 3.14, `pg-protocol` 1.16, `pg-types` 2.2, `pgpass` 1.0, `pg-connection-string` 2.14 and the optional `pg-cloudflare` 1.4 have no `install`, `preinstall` or `postinstall` script either.
- Its only native part, `pg-native`, is an optional peer dependency that we don't install.

Rejected:
- `postgres` (porsager): fine, but its tagged-template API would change every query string again.
- An ORM: it would rewrite all 257 queries and add a large surface.

**Settings the engine sets:**
- `pg.types.setTypeParser(20, Number)`: `int8`, which `COUNT(*)`, `SUM` of integers and identity ids return, comes back as a number like on SQLite. The ids stay far below 2^53.
- `pg.types.setTypeParser(1700, Number)` for `numeric`, if any column uses it. The schema uses `double precision` for money, as SQLite's REAL.

### 4.2 Roles

`wa_owner` owns the database objects and runs the migrations. `wa_app` is the only role the agent runs as. Bootstrap SQL, run once as a superuser by `npm run cli -- db-bootstrap` (S2.3) or by hand on the Mac:

```sql
ALTER DEFAULT PRIVILEGES FOR ROLE wa_owner IN SCHEMA public GRANT USAGE, SELECT ON SEQUENCES TO wa_app;
```

- `wa_app` gets no `CREATE` on the schema, so it can run no DDL.

### 4.3 The schema, as Postgres migrations

These are new files: `src/store/pg/migrations.ts`, numbered `P1`, `P2` and so on, recorded in `pg_schema_version`. The SQLite migrations v1 to v12 are never edited. The Postgres schema is the **merged result** of v1 to v12, written once.

| SQLite | Postgres | Why |
|---|---|---|
| `INTEGER PRIMARY KEY` | `bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY` | Ids stay unique across customers, so a URL id can never point at a row of another customer that happens to share it |
| 0/1 `INTEGER` flags | `smallint NOT NULL CHECK (x IN (0, 1))` | The queries' `= 1` and the code's `=== 1` stay as they are |
| ISO time `TEXT` | `text` (ISO 8601, UTC, with milliseconds) | String order equals time order, as now. Moving to `timestamptz` is a later, separate migration |
| `REAL` | `double precision` | |
| `BLOB` (session stores) | `bytea` | |
| `UNIQUE (a, b)` | `UNIQUE (tenant_id, a, b)` | Each customer has its own codes, dates and keys |
| `REFERENCES clients(id)` | `FOREIGN KEY (tenant_id, client_id) REFERENCES clients (tenant_id, id)`, with `UNIQUE (tenant_id, id)` on every parent | Foreign-key checks bypass RLS, so a composite key is what stops a row from pointing at another customer's parent |

Every customer table also gets these, in that order:

```sql
tenant_id uuid NOT NULL DEFAULT current_setting('app.tenant_id')::uuid REFERENCES tenants (id),
```

- An index starting with `tenant_id` comes for free from the composite unique keys, plus `CREATE INDEX <t>_tenant ON <t> (tenant_id)` where a table has none.
- The **default** means no INSERT in the code names `tenant_id`, and no query text changes for it.
- Without the setting, `current_setting('app.tenant_id')` (no `true`) raises, so an INSERT outside `withTenant` fails loudly.

### 4.5 `withTenant` and the tenant-bound `Db`

`src/store/engine/pg.ts` is **the only file that imports `pg`**. It exports `openPgPool(url)`, `withTenant(pool, tenantId, fn, { write })` and `PgTenantDb`, which implements the S1 `Db` interface for one customer. Every statement and every transaction runs inside `withTenant`. That is why S1's "use the handle you are given" rule is enough to keep RLS correct.

```ts
import pg from 'pg';
import { translate } from './translate.ts';
import type { Db, Params, RunResult, Sql } from './types.ts';

pg.types.setTypeParser(20, (v) => Number(v));
const UUID = /^[0-9a-f]{8}-[0-9a-f]{4}-[1-8][0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/;

export function openPgPool(url: string): pg.Pool {
  return new pg.Pool({ connectionString: url, max: 10, idleTimeoutMillis: 30_000, application_name: 'wa-agent' });
}

function handle(c: pg.PoolClient, depth = { n: 0 }): Sql {
  const query = async (sql: string, p?: Params) => {
    const t = translate(sql, p);
    return c.query(t.text, t.values);
  };
  return {
    get: async (sql, p) => (await query(sql, p)).rows[0],
    all: async (sql, p) => (await query(sql, p)).rows,
    run: async (sql, p): Promise<RunResult> => ({ changes: (await query(sql, p)).rowCount ?? 0 }),
    exec: async (sql) => void (await c.query(sql)),
    tx: async (fn) => {
      const name = `sp${++depth.n}`;
      await c.query(`SAVEPOINT ${name}`);
      try {
        const r = await fn(handle(c, depth));
        await c.query(`RELEASE SAVEPOINT ${name}`);
        return r;
      } catch (e) {
        await c.query(`ROLLBACK TO SAVEPOINT ${name}`);
        throw e;
      }
    },
  };
}

/**
 * The only way to the database on Postgres: one transaction with app.tenant_id set for it alone (set_config's third
 * argument, true), so a pooled connection never carries a customer's id into the next use. A write transaction also
 * takes the customer's advisory lock: one writer per customer, as SQLite's queue gives one writer per process.
 */
export async function withTenant<T>(pool: pg.Pool, tenantId: string, fn: (q: Sql) => Promise<T>, o: { write: boolean }): Promise<T> {
  if (!UUID.test(tenantId)) throw new Error('withTenant needs a customer id');
  const c = await pool.connect();
  try {
    await c.query('BEGIN');
    await c.query("SELECT set_config('app.tenant_id', $1, true)", [tenantId]);
    if (o.write) await c.query("SELECT pg_advisory_xact_lock(hashtextextended('wa:' || $1, 0))", [tenantId]);
    const r = await fn(handle(c));
    await c.query('COMMIT');
    return r;
  } catch (e) {
    await c.query('ROLLBACK').catch(() => undefined);
    throw e;
  } finally {
    c.release();
  }
}

/** One customer's database: every call is its own withTenant transaction. */
export class PgTenantDb implements Db {
  readonly engine = 'postgres' as const;
  readonly #pool: pg.Pool;
  readonly tenantId: string;

  constructor(pool: pg.Pool, tenantId: string) {
    this.#pool = pool;
    this.tenantId = tenantId;
  }

  get<T>(sql: string, p?: Params): Promise<T | undefined> {
    return withTenant(this.#pool, this.tenantId, (q) => q.get<T>(sql, p), { write: false });
  }
  all<T>(sql: string, p?: Params): Promise<T[]> {
    return withTenant(this.#pool, this.tenantId, (q) => q.all<T>(sql, p), { write: false });
  }
  run(sql: string, p?: Params): Promise<RunResult> {
    return withTenant(this.#pool, this.tenantId, (q) => q.run(sql, p), { write: true });
  }
  exec(): Promise<void> {
    return Promise.reject(new Error('exec is for migrations, which run as wa_owner (db-migrate)'));
  }
  tx<T>(fn: (q: Sql) => Promise<T>): Promise<T> {
    return withTenant(this.#pool, this.tenantId, fn, { write: true });
  }
  async close(): Promise<void> {
    await this.#pool.end();
  }
}
```

### 4.6 SQL that works on both engines

`src/store/engine/translate.ts` turns the SQLite text into Postgres text once per statement, and caches it:
- `@name` and `?` become `$1…$n`, outside quoted strings. A repeated `@name` keeps its number, and a statement that mixes both styles throws.
- A camelCase alias, `AS clientCode`, becomes `AS "clientCode"`, so the row keys stay the same. Postgres folds unquoted names to lower case.
- `json_each(X)` becomes `json_array_elements_text((X)::json)`. The column is called `value` in both.
- `instr(a, b)` becomes `strpos(a, b)`.
- `ON CONFLICT (cols)` becomes `ON CONFLICT (tenant_id, cols)`. That is correct because every unique key in the Postgres schema starts with `tenant_id` (4.3).

These can't be translated safely, so S2.5 changes the source to SQL both engines run:
- `INSERT OR IGNORE` (1) becomes `ON CONFLICT DO NOTHING`;
- `sqlite_master` (2) moves behind `db.engine`.

### 4.8 A Postgres for tests, on Windows and on the Mac

**Choice:** a throwaway real Postgres 17 server that the test runner starts, then stops.
- **On Windows:** from Docker's `postgres:17-alpine` image. Docker Desktop is already installed on this PC, and no Postgres is.
- **On the Mac:** from the Homebrew `postgresql@17` binaries, which the cutover installs anyway (design 8.4). It uses `initdb` into a temporary folder, on its own port, **never the production cluster**, so a test can't touch real data, and the production Mac doesn't need Docker.

**Why not the alternatives:**
- `embedded-postgres`: its platform packages run a `postinstall` script, weigh about 109 MB each, and are 18.x betas.
- PGlite: Postgres in WASM, single-user, without the network protocol `pg` uses. It would not test the production path.

```ts
// src/store/engine/translate.ts
import type { Params } from './types.ts';

const cache = new Map<string, { text: string; names: string[] | null; count: number }>();

/** Splits SQL into code and quoted parts, so rewrites never touch text inside '…'. */
function parts(sql: string): { code: boolean; s: string }[] {
  const out: { code: boolean; s: string }[] = [];
  const re = /'(?:[^']|'')*'/g;
  let at = 0;
  for (const m of sql.matchAll(re)) {
    out.push({ code: true, s: sql.slice(at, m.index) }, { code: false, s: m[0] });
    at = m.index + m[0].length;
  }
  out.push({ code: true, s: sql.slice(at) });
  return out;
}

function compile(sql: string): { text: string; names: string[] | null; count: number } {
  const names: string[] = [];
  let count = 0;
  let positional = false;
  const text = parts(sql).map(({ code, s }) => {
    if (!code) return s;
    return s
      .replace(/@([A-Za-z_][A-Za-z0-9_]*)|\?/g, (m, name: string | undefined) => {
        if (name === undefined) {
          positional = true;
          return `$${++count}`;
        }
        const i = names.indexOf(name);
        if (i >= 0) return `$${i + 1}`;
        names.push(name);
        return `$${names.length}`;
      })
      .replace(/\bAS\s+([a-z][A-Za-z0-9_]*[A-Z][A-Za-z0-9_]*)\b/g, 'AS "$1"')
      .replace(/\bjson_each\(([^()]*)\)/g, 'json_array_elements_text(($1)::json)')
      .replace(/\binstr\(/g, 'strpos(')
      .replace(/\bON CONFLICT \(/g, 'ON CONFLICT (tenant_id, ');
  }).join('');
  if (positional && names.length > 0) throw new Error('a statement mixes ? and @name values');
  return { text, names: positional ? null : names, count: positional ? count : names.length };
}

export function translate(sql: string, params?: Params): { text: string; values: unknown[] } {
  let c = cache.get(sql);
  if (!c) {
    c = compile(sql);
    if (cache.size > 1_000) cache.clear();
    cache.set(sql, c);
  }
  if (c.names === null) return { text: c.text, values: Array.isArray(params) ? [...params] : [] };
  const named = (params ?? {}) as Record<string, unknown>;
  return {
    text: c.text,
    values: c.names.map((n) => {
      if (!Object.hasOwn(named, n)) throw new Error(`no value for @${n}`);
      return named[n];
    }),
  };
}
```

```ts
export async function openStore(env: Env): Promise<Db> {
  if (env.DB_ENGINE === 'sqlite') return openDb(trackerDbPath(env.DATA_DIR));
  const pool = openPgPool(env.DATABASE_URL!);
  const db = new PgTenantDb(pool, env.TENANT_ID);
  const v = (await db.get<{ v: number | null }>('SELECT wa_schema_version() AS v'))?.v ?? 0;
  if (v !== PG_LATEST) {
    await pool.end();
    throw new Error(`Postgres is at P${v}, this version needs P${PG_LATEST}: run npm run cli -- db-migrate`);
  }
  return db;
}
```

```ts
describe.runIf(process.env.DB_ENGINE === 'postgres')('RLS: customer A and customer B', () => {
  let pool: pg.Pool;

  let B: string;

      expect((await q.run(`DELETE FROM ${t}`)).changes).toBe(0);
```
