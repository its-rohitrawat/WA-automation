# Phase 2b amendment: local speech-to-text for voice notes (2026-10-26)

> **Status: owner decision, 2026-10-26.** Voice notes are transcribed by an open-source model running on the office machine, not by a paid service. The paid adapters stay in the code, off by default. Meetings (Phase 3) are unchanged.
>
> This amends the Phase 2b plan (`2026-10-23-phase-2b-voice-notes.md`). Where the two disagree, this file wins.

## The machine

- Mac Pro, Intel Xeon W-3223 (8 cores, AVX-512), 32 GB RAM, no usable GPU, so no Metal acceleration (CPU only).
- No PyTorch after 2.2.2 on Intel macOS, so no Python ML stacks: C++ runtimes built from source with the Xcode tools and cmake.
- ffmpeg and Homebrew are installed. macOS support is on main (PR #3, `docs/SETUP-mac.md`).

### Runtimes and exact command lines

**transcribe.cpp** ([repo](https://github.com/handy-computer/transcribe.cpp), MIT, v0.4.1 of 2026-10-22). It runs Voxtral and Qwen3-ASR with one CLI. Flags from the CLI source ([main.cpp](https://raw.githubusercontent.com/handy-computer/transcribe.cpp/main/examples/cli/main.cpp), [asr.cpp](https://raw.githubusercontent.com/handy-computer/transcribe.cpp/main/examples/cli/asr.cpp)):

```
transcribe-cli -m <model.gguf> --threads <N> -q -o <out.txt> [-l hi] <note.wav>
```

- The input must be a 16 kHz mono WAV.
- `-o` writes only the transcript text plus a newline.
- `-q` silences library logs; logs and errors go to stderr.
- The short `-t` means *translate*, not threads: always use `--threads`.
- `-l <code>` is documented for Voxtral, with Hindi listed ([docs](https://raw.githubusercontent.com/handy-computer/transcribe.cpp/main/docs/models/voxtral-mini-3b-2507.md)). For Qwen3-ASR it is **not confirmed** to map `hi`, so it is not passed (auto-detect).
- Neither model gives timestamps here. Voice notes don't need them.

**whisper.cpp** ([repo](https://github.com/ggml-org/whisper.cpp), MIT). Flags from the [CLI README](https://raw.githubusercontent.com/ggml-org/whisper.cpp/master/examples/cli/README.md) and [cli.cpp](https://raw.githubusercontent.com/ggml-org/whisper.cpp/master/examples/cli/cli.cpp):

```
whisper-cli -m <ggml-large-v3-turbo.bin> -f <note.wav> -l hi -t <N> -np -nt -otxt -of <out base>
```

- The default language is `en`, so `-l` is always passed.
- `-np` silences prints; `-nt` gives no timestamps.
- `-otxt -of <base>` writes `<base>.txt`. This is to be confirmed by the owner's local check, which reports a missing file clearly.
- Never `-tr` (translate).

**Dropped: Voxtral through llama.cpp.** `llama-mtmd-cli` supports Voxtral, but it needs a separate mmproj file, has no language hint (transcription is a free-form prompt the model may paraphrase or translate), and its CLI is labelled experimental. transcribe.cpp does the same job with a documented hint.

### Builds on Intel macOS (CPU only)

- **transcribe.cpp:** `cmake -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j`.
  - Metal is off by default on x86_64.
  - The vendored ggml keeps `GGML_NATIVE` on, so AVX-512 is used.
  - A prebuilt `transcribe-native-0.4.1-macos-x86_64-cpu.tar.gz` exists; whether it uses AVX-512 is not stated, so SETUP builds from source.
- **whisper.cpp:** release tag v1.9.5 (`git clone --branch v1.9.5`), then `cmake -B build -DGGML_METAL=OFF && cmake --build build -j --config Release`. `GGML_NATIVE` defaults on.

## Design

### Settings (`src/config/env.ts`, additive; `STT_PROVIDER` and meetings are unchanged)

| Setting | Values | Default |
|---|---|---|
| `VOICE_STT_PROVIDER` | `local \| sarvam \| elevenlabs \| openai \| none` | `none` (voice notes off, as in 2a) |
| `STT_LOCAL_ENGINE` | `voxtral \| qwen3-asr \| whisper` | `voxtral` |
| `STT_LOCAL_BIN` | absolute path to `transcribe-cli` (voxtral, qwen3-asr) or `whisper-cli` (whisper) | none; required for `local` |
| `STT_LOCAL_MODEL` | absolute path to the model file | none; required for `local` |
| `STT_LOCAL_THREADS` | 1–64 | 8 |
| `STT_LOCAL_TIMEOUT_SECONDS` | 60–7200 | 1800 |
| `STT_LOCAL_LANGUAGE` | `hi \| en \| auto` | `hi` (passed to voxtral and whisper; qwen3-asr always auto-detects) |

- A paid voice provider uses the one key `STT_API_KEY`, so it must equal `STT_PROVIDER`. A different value is refused, naming `VOICE_STT_PROVIDER`.
- `local` needs no key.
- Errors name the setting only, never a value.
- The paths are checked when the service starts, without crashing it:
  - each must exist and be a regular file;
  - if either is missing, voice transcription is off, a warning is logged with the setting's name, and the health line says "⚠️ Voice notes are not being transcribed: the local speech engine is not set up (STT_LOCAL_BIN)".
  - WhatsApp tracking keeps running.

### The local engine (`src/stt/local.ts`, new)

- `LocalEngine` with `transcribe(wavPath, signal?) → { text }`.
- It builds the argument array per engine exactly as above. Only `-o` / `-of` paths in the note's own temporary folder, the configured paths, and fixed flags are passed. Nothing from the sender is passed.
- It runs through the existing `RunFile` (`src/stt/audio.ts`): `execFile`, no shell, `minimalEnv()`, the timeout, and the abort signal.
- **One run at a time** (a promise chain inside the engine), so 8 cores are not shared by three models. Pictures still use the other media queue slots.
- Outcomes:
  - exit code 0 and an output file: the text, trimmed, with lines joined by single spaces. An empty file gives empty text, so the note becomes "no speech".
  - a non-zero exit, a missing output file, the timeout, or an abort: `LocalEngineError` with a code (`exit_<n>`, `no_output`, `timeout`, `aborted`).
  - stderr is never logged or put in an error: it may echo audio-derived text.
- Cost is $0. No SpendGuard hold, no `withSttHold`, no forget step, no network.

### Into the existing pipeline (after Task 5's fix round merges)

- `src/stt/audio.ts` gains `Ffmpeg.toWav(input, output, signal?, { maxSeconds })`. It is additive, with `SAFE_INPUT` and `-t`, and makes a 16 kHz mono `pcm_s16le` WAV. The owner's "convert every voice note first" rule stays: local engines get the WAV, paid ones the MP3 as before.
- `createVoiceTranscriber` reads `VOICE_STT_PROVIDER`. For `local` it builds a `VoiceTranscriber` whose `prepare` converts to WAV and measures it, and whose `transcribe` calls `LocalEngine`. It sets `costsNothing: true`, `ceilingUsd() = 0` and `canForget: false`.
- The extractor skips the hold for a transcriber that costs nothing: no `too_costly`, no spend row. Everything else stays: forwarded (V4), the cap (`too_long`), revoked, dispose, no_speech.
- Processor: a `LocalEngineError` is a counted retry (3 attempts; it costs nothing). An abort at shutdown gives the attempt back.
- App: `stop()` aborts a local run in flight. It is free, so the note is simply tried again after restart; no child process is left running.
- Backlog command (Task 8): the cost lines say "$0 (local engine)". Every file still needs ffmpeg.
- Health (Task 9): the "local speech engine is not set up" line above.
- V7 privacy: with `local`, no audio leaves the machine and there are no provider steps. Clients can be told voice notes are transcribed on the office computer.

### The owner's check (`npm run stt:local-check -- <audio file>`)

- It loads the settings, converts the file with ffmpeg to a 16 kHz WAV in a temporary folder, and runs the configured engine once.
- It prints the engine, the audio length, the wall time, the realtime factor and the transcript **to the owner's terminal only**. Nothing is logged or stored, and no network is used.
- It is used to choose between Voxtral and Qwen3-ASR on real Hinglish notes. Voxtral on this CPU may be slower than realtime, so a 10-minute note could take 10–20 minutes.

### Docs (`docs/SETUP-mac.md`, a new "Voice notes: local speech-to-text" section)

- Build transcribe.cpp (and optionally whisper.cpp) with cmake.
- Download the model from the official repo, and check `shasum -a 256` against the table above.
- Set `VOICE_STT_PROVIDER=local`, `STT_LOCAL_ENGINE`, `STT_LOCAL_BIN` and `STT_LOCAL_MODEL`.
- Run the check on two or three real notes, then restart the service.

## Risks

- **Speed:** Voxtral may be slower than realtime on this CPU. Long notes hold a client's update for at most 30 minutes (V1). After that the update goes on, and the note is re-checked when its transcript arrives (12h). Qwen3-ASR is the faster switch.
- **Hinglish:** accuracy and script are unknown until the owner's check.
- **transcribe.cpp is young** (v0.4, with flag migrations at 0.2 and 0.4). Pin the version in SETUP; the check script catches flag changes.
